# 第 03 课（精讲版）· 请求层：一条数据怎么从服务器走到你的页面

> 本课是"精讲版"标准：**每一段代码 → 逐行注释 → 为什么这么写 → 不这么写会怎样 → 常见错误**。
> 涉及文件：`src/utils/request.js`、`src/main.js`（拦截器）、`src/utils/average.js`（顺带）

## 零、本课目标

1. 能说清 `axios` 一次请求从发出到回调，中间经过哪 4 层数据
2. 能背出 `$get` 和 `$post` 的返回值差异（这是本项目最容易搞混的地方）
3. 能解释 `baseURL`、绝对 URL、devServer proxy 三者的优先关系
4. 能自己用浏览器/PowerShell 直接调接口，判断"是前端问题还是后端没数据"
5. 能写出健壮的取数代码（空数组不崩、错误有兜底）

## 一、前置知识补给箱（0 基础也能跟上）

### 1.1 axios 是什么

浏览器原生只有 `fetch` 和 `XMLHttpRequest`。`axios` 是在 `XMLHttpRequest` 上封的一层，
好处是：自动 JSON 解析、统一拦截器、超时设置、取消请求。

```js
// 原生 fetch 的写法
fetch("/mountain?topicId=35").then(r => r.json()).then(data => ...)

// axios 的写法（自动 .json()，还能挂拦截器）
axios.get("/mountain", { params: { topicId: 35 } }).then(res => res.data)
```

**为什么本项目用 axios 而不用 fetch**：需要拦截器（统一加 baseURL/token）和超时。

### 1.2 Promise 是什么

一个"未来会有结果"的盒子，三种状态：

```
pending（等） → fulfilled（成功，走 then） 
             ↘ rejected（失败，走 catch）
```

```js
axios.get(url)          // 返回 Promise
  .then(res => { ... }) // 成功
  .catch(err => { ... })// 失败（网络断了、4xx、5xx、超时）
```

**重要**：后端返回 `{"code":500}` 但 HTTP 状态是 200 时，**不会**走 catch。
所以"后端业务错误"要自己判断 `res.data.code`。

### 1.3 async/await 是什么

`Promise` 的语法糖，让异步代码看起来像同步：

```js
// then 写法
getData() {
  this.$get(url, p).then(res => { this.a = res.data[0].temperature })
}

// async/await 写法（等价，但更好读、能 try/catch）
async getData() {
  try {
    const res = await this.$get(url, p)
    this.a = res.data[0].temperature
  } catch (e) {
    console.error(e)
  }
}
```

本项目**99% 用 then**（历史风格），你在 `YuganAqua` 里能看到少数 `await`。
两种都能用，看团队约定。

### 1.4 `params` vs `data`（高频错误，务必记住）

| 位置 | 出现在 | 实际效果 |
|---|---|---|
| `params` | URL 后面 | `GET /mountain?topicId=35` |
| `data` | 请求体 | `POST` body（GET 请求里会被**忽略**） |

```js
// ✅ 正确：GET 用 params
axios.get("/mountain", { params: { topicId: 35 } })

// ❌ 错误：GET 用 data —— 参数根本不会发出去，后端收到空
axios.get("/mountain", { data: { topicId: 35 } })
```

登录接口用的是 `params` 但方法是 `post`（`Login.vue`），
结果参数拼在 URL 上而不是 body 里 —— 后端如果只读 body，就会登不上。

### 1.5 `baseURL` 与绝对 URL 的优先级

```
axios.get("mountain")                       → ${baseURL}/mountain       ✅ 用 baseURL
axios.get("/mountain")                      → ${baseURL}/mountain       ✅ 用 baseURL
axios.get("http://1.2.3.4:8090/mountain")   → http://1.2.3.4:8090/...   ❌ 完全忽略 baseURL
```

**这就是本项目"配了 proxy 但没生效"的根本原因**：页面里写的全是绝对 URL。

### 1.6 拦截器是什么

```
请求发出前 ──→ [请求拦截器] ──→ 服务器 ──→ [响应拦截器] ──→ then
```

作用：统一加头、统一改地址、统一处理 401。
本项目只用了请求拦截器，**没有响应拦截器**（所以错误处理全靠每个页面自己 catch，基本没写）。

## 二、逐行精读 `src/utils/request.js`（92 行）

### 2.1 第 1~13 行：配置区

```js
import axios from "axios";
// 接口公共部分
// 本地接口

// const commonUrl = "http://localhost:8080/";
// 线上接口
//axios.defaults.baseURL = "https://mqtt.vikedata.com/mqtt-cli/api/v1/"

//改成用ip访问
// 全局强制设置 baseURL
const baseURL = "http://121.5.9.113:8090"
axios.defaults.baseURL = baseURL
axios.defaults.timeout = 30000
```

| 行 | 这一行在干什么 | 为什么 / 不写会怎样 |
|---|---|---|
| `import axios` | 引入库 | —— |
| 注释掉的 `commonUrl` | 历史配置残留 | 说明这套代码换过 3 个后端地址：localhost → vikedata 域名 → IP |
| `const baseURL = "..."` | 抽成常量 | 好处：只有一处要改。坏处：仍然是**硬编码**，没法区分开发/生产 |
| `axios.defaults.baseURL` | 设全局默认前缀 | 之后 `axios.get("/mountain")` 会自动拼成 `http://121.5.9.113:8090/mountain` |
| `axios.defaults.timeout = 30000` | 30 秒超时 | 不设的话浏览器默认可能等几分钟；大屏场景 30 秒足够 |

⚠️ **问题**：`baseURL` 是**模块级副作用**，只要 import 了这个文件，全局 axios 就被改了。
所以 `Login.vue` 里 `this.$axios({url: "http://..."})` 这种绝对地址才"看起来正常"。

**更规范的做法**（以后你改造时用）：

```js
// .env.development →  VUE_APP_BASE_URL=http://127.0.0.1:8090
// .env.production  →  VUE_APP_BASE_URL=https://api.example.com
const baseURL = process.env.VUE_APP_BASE_URL || "http://121.5.9.113:8090"
```

### 2.2 第 15~27 行：请求拦截器

```js
axios.interceptors.request.use(
  config => {
    // 如果url里有旧域名，直接替换
    if (config.url.includes("jxautts.top:444")) {
      config.url = config.url.replace("https://jxautts.top:444", baseURL)
    }
    // 强制覆盖baseURL，防止被其他地方修改
    config.baseURL = baseURL
    return config;
  },
  error => Promise.reject(error)
);
```

逐行：

| 行 | 在干什么 | 为什么 |
|---|---|---|
| `interceptors.request.use(fn, errFn)` | 注册"请求发出前"的钩子 | —— |
| `config.url.includes("jxautts.top:444")` | 检测是不是旧域名 | 项目换过域名，老代码里还写着 `https://jxautts.top:444` |
| `config.url.replace(...)` | 换成新 IP | 这样**不用改 100 个文件**就能换后端地址（一个很实用的临时手段） |
| `config.baseURL = baseURL` | 每次请求都强制覆盖 | 作者注释写得很清楚："防止被其他地方修改" |
| `return config` | **必须返回** | 不返回 config，请求会以 `undefined` 发出去 → 报错 |
| `error => Promise.reject(error)` | 请求阶段就出错的兜底 | 一般很少触发 |

⚠️ **这一行有隐患**：`config.url.includes(...)` 要求 `config.url` 是字符串。
如果有人写 `axios.get()` 不传 url，这里会抛 `Cannot read property 'includes' of undefined`。
稳妥写法：`if ((config.url || "").includes(...))`。

### 2.3 第 39~50 行：`postRequest`

```js
export function postRequest(url, params) {
  return new Promise((resolve, reject) => {
    axios
      .post(url, params)
      .then((res) => {
        resolve(res);        // ★ 返回整个 axios response
      })
      .catch((err) => {
        reject(err);
      });
  });
}
```

**这段代码有三个知识点：**

**① 为什么要 `new Promise` 包一层？**
因为要"改造"返回值：axios 返回的是 `res`，这里原样 resolve，其实**可以直接写成**：

```js
export function postRequest(url, params) {
  return axios.post(url, params)   // 完全等价，少一层
}
```

作者这么写是为了和下面 `getRequest` **保持结构对称**，属于"过度包装"。

**② `resolve(res)` 和 `resolve(res.data)` 的区别（本课核心）**

看数据从服务器回来的完整层级：

```
服务器返回的 JSON 文本:  {"code":200,"data":[{...}]}
        ↓ axios 自动 JSON.parse，包进 response 对象
第①层  response      = { status:200, headers:{…}, data:{code:200,data:[…]} , config:{…} }
        ↓ resolve(res)          ← postRequest 停在这一层
第②层  response.data = {code:200, data:[…]}        （后端 body）
        ↓ resolve(res.data)     ← getRequest 停在这一层
第③层  body.data     = [{…}, {…}]                   （记录数组）
        ↓ [0]
第④层  record        = {temperature:"10.40", ts:"…"}
```

所以：

```js
this.$post(url, p).then(res => {
  res.data.data   // ← 要挖两层才到数组
})

this.$get(url, p).then(res => {
  res.data        // ← 只要挖一层
})
```

> **一句话记忆**：`$post` 给你"信封"，`$get` 已经帮你拆了信封，只剩信纸。

**③ 为什么 `.then` 里还要 `resolve`？**
因为 `new Promise` 的执行器里必须手动调用 `resolve/reject`，否则外层永远 pending（"回调地狱"的来源）。

### 2.4 第 52~69 行：被注释掉的 `postBodyRequest`

```js
// export function postBodyRequest(url, data) {
//   return new Promise((resolve, reject) => {
//     axios.post(url, data).then(...)
//   });
// }
```

它和 `postRequest` **完全一样**（axios 的 `post(url, data)` 本来就是 body 传参）。
作者可能以为自己写了个"body 版"，其实是重复的，注释掉是对的。

### 2.5 第 81~91 行：`getRequest`

```js
export function getRequest(url, params) {
  return new Promise((resolve, reject) => {
    axios
      .get(url, { params: params })   // ← 注意这里：{ params } 是把对象拼到 URL 上
      .then((res) => {
        resolve(res.data);            // ★ 只返回 body
      })
      .catch((err) => {
        reject(err);
      });
  });
}
```

关键在 `axios.get(url, { params })`：

```js
// 你写
this.$get("/mountain", { topicId: "35", timeType: "hour" })
// 实际请求
GET http://121.5.9.113:8090/mountain?topicId=35&timeType=hour
```

而 `resolve(res.data)` 让调用方少写一层 —— 这就是为什么全项目都在写 `res.data`。

### 2.6 小结：`request.js` 的 4 个真实问题

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | `baseURL` 硬编码 | 换环境改代码 | 用 `.env` 环境变量 |
| 2 | `$get` / `$post` 解包层级不一致 | 调用方要记两套 | 统一 `resolve(res.data)` |
| 3 | `new Promise` 多余包装 | 代码更长、易忘 resolve | 直接 `return axios.get(...)` |
| 4 | 没有响应拦截器 | 401/500 无人统一处理 | 加 `interceptors.response` |

## 三、`main.js` 里的第二个拦截器（第 23~29 行）

```js
axios.interceptors.request.use((config) => {
  //为请求头对象添加token验证的 Authorization 字段
  if (config.url == "http://121.5.9.113:8090/api/v1/export")
    config.headers.Authorization = window.localStorage.getItem("token");
  console.log(config);
  return config;
});
```

| 行 | 问题 |
|---|---|
| `config.url == "..."` | **全等比较**，页面实际请求的是 `.../api/v1/allMsg/export` → **永远不成立** |
| `window.localStorage` | 浏览器里 `localStorage` 本身就是全局，加 `window.` 无害但多余 |
| 没判断 token 是否为 null | 会把 `"null"` 字符串写进请求头 |
| `console.log(config)` | **会把 token 打进控制台**，属于信息泄露 |

**修好它**（三行）：

```js
axios.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token && config.url.includes("/export")) {
    config.headers.Authorization = token;
  }
  return config;
});
```

> 这个 bug 的意义不只是"少个 token"——它说明**同一个功能被两处代码各管一半**（main.js 管加头，ExportPage 管发请求），
> 两边一旦对不上就断链。改造思路：把请求封装成 `exportData(params)` 一个函数，头由它自己加。

## 四、现场实测：三种接口长什么样（我实际调出来的）

### 4.1 自己动手调接口的 3 种方式

```powershell
# 方式 1：浏览器地址栏直接开（最快，看 GET）
http://121.5.9.113:8090/mountain?topicId=35&timeType=realTime

# 方式 2：PowerShell
Invoke-WebRequest -Uri "http://121.5.9.113:8090/mountain?topicId=35&timeType=realTime" -UseBasicParsing | Select-Object -ExpandProperty Content

# 方式 3：F12 → Network → 点某个请求 → Response 标签
```

### 4.2 三个接口的真实返回（同一张表，同一套结构）

| 接口 | 实测长度 | 第一条记录时间 |
|---|---|---|
| `/mountain?topicId=35&timeType=realTime` | 11879 字节 | `2025-11-17 02:20:01` |
| `/api/v1/msg?topicId=31&timeType=realTime` | 11507 字节 | `2026-03-20 05:38:39` |
| `/api/v1/allMsg?topicId=37&timeType=realTime` | 11886 字节 | `2026-04-05 17:10:05` |

返回体结构（三个接口一模一样）：

```json
{
  "code": 200,
  "success": true,
  "message": "ok",
  "data": [
    {
      "id": 1519675282649595580,
      "area": "zgdq",
      "clientId": "31-1",
      "topic": "31",
      "ts": "2026-03-20 05:38:39",
      "receiveTime": "2026-03-20 05:39:39",
      "temperature": "11.5",
      "humidity": "98.2",
      "illuminance": "0",
      "co2": "672",
      "sunRadia": "3",
      "soilTemp": "54.9",
      "soilHum": "",
      "conductivity": "",
      "pm25": "9",
      "pm10": null,
      "windSpeed": "0",
      "windDirection": 0,
      "rainfall": "",
      "allRainfall": null
    }
  ]
}
```

**三个重要发现：**

**① 数值全是字符串或 null，不是数字**

```json
"temperature": "11.5"     ← 字符串
"pm10": null              ← null
"soilHum": ""             ← 空字符串
```

这就是为什么项目里到处是这种写法：

```js
(item.temperature - 0).toFixed(2)   // 字符串减 0 → 隐式转数字 → 再格式化
```

`"11.5" - 0` = `11.5`（数字），这是 JS 的隐式类型转换。
⚠️ 如果值是 `""`，`"" - 0` = `0`（居然不报错）；如果是 `null`，`null - 0` = `0`；如果是 `"abc"`，结果是 `NaN`。
所以项目里还有 `x ? x : "0"` 的兜底 —— **两层防护，都是被脏数据逼出来的**。

**② 湿度 104.90% —— 真实脏数据**

井冈山那条记录 `humidity: "104.90"`，相对湿度物理上不可能超过 100%。
说明传感器有偏差/未校准。前端没有做范围校验，直接显示 104.90%rh 了。
**这类问题属于"数据质量"，不是前端 bug，但前端可以兜（clamp 到 100）**。

**③ 请求不存在的网关，依然返回 200**

```powershell
# topicId=9999（根本不存在）
GET /mountain?topicId=9999&timeType=realTime
→ {"code":200,"success":true,"message":"ok","data":[]}
```

**这是本课最关键的一条**：后端**永远返回 200**，没有数据就给空数组。
所以前端**无法区分**"网关挂了""网关不存在""这段时间没采集"——全都长一样。

于是出现两种完全不同的表现：

```js
// 情况 A：resData.map(...)  ← 空数组也能跑，得到 []
this.arrivedTime = resData.map(item => item.ts.slice(11,13) + "点")   // → []

// 情况 B：resData[0].temperature  ← 空数组直接崩
this.temp = resData[0].temperature   // TypeError: Cannot read property 'temperature' of undefined
```

**这解释了你在项目里看到的现象**：曲线是空的（走 A），但数字是 0 而不是报错（因为 B 那段被 try 隐式吞了？不是，是因为这个网关恰好有数据）。

|---|---|---|---|


## 五、在组件里怎么用（3 种写法，逐个对比）

### 写法 1：`then`（项目现状，90% 的代码）

```js
getData() {
  this.$get("http://121.5.9.113:8090/mountain", {
    topicId: "35",
    timeType: "realTime",
  }).then((res) => {
    const list = res.data || [];      // ← 兜底：万一是 null
    const rec = list[0] || {};        // ← 兜底：万一是空数组
    this.real_airTemData = rec.temperature || "0";
  }).catch((err) => {
    console.error("取数失败", err);
  });
}
```

✅ 优点：和项目风格一致；❌ 缺点：嵌套层级多，错误处理容易忘（项目里几乎全忘了）。

### 写法 2：`async/await`（推荐）

```js
async getData() {
  try {
    const res = await this.$get("http://121.5.9.113:8090/mountain", {
      topicId: "35",
      timeType: "realTime",
    });
    const rec = (res.data || [])[0] || {};
    this.real_airTemData = rec.temperature ?? "0";     // ?? 比 || 更准（0 不会被当假值）
  } catch (e) {
    console.error("取数失败", e);
    this.$message?.error("数据获取失败");               // element-ui 的提示
  }
}
```

✅ 好读、能 try/catch、能 `await` 多次顺序调用；❌ 需要 Babel（项目已有）。

### 写法 3：并发（多接口一起要，`YuganAqua` 用了）

```js
// ❌ 串行：等 6 次，慢
const a = await this.$get(url1, p)
const b = await this.$get(url2, p)
const c = await this.$get(url3, p)

// ✅ 并发：同时发，一起等
const [a, b, c] = await Promise.all([
  this.$get(url1, p),
  this.$get(url2, p),
  this.$get(url3, p),
])
```

余干水产有 6 个池塘（topic 37/40/41/42/43/44），串行要 6 个 RTT，并发只要 1 个。

## 六、5 个必踩的错误（都能现场复现）

### 错误 1：忘记多挖一层 `.data`

```js
// ❌ 以为 res 就是数组
this.$get(url).then(res => {
  res.map(...)        // TypeError: res.map is not a function
})

// ✅
this.$get(url).then(res => {
  res.data.map(...)
})
```

### 错误 2：GET 用 `data` 传参

```js
// ❌ 参数不会出现在 URL 上，后端收到空
axios.get("/mountain", { data: { topicId: 35 } })

// ✅
axios.get("/mountain", { params: { topicId: 35 } })
```

### 错误 3：写全 URL，导致 baseURL 和 proxy 全失效

```js
// ❌ 跨域靠后端 CORS；换环境要改 100 处；devServer proxy 完全不参与
this.$get("http://121.5.9.113:8090/mountain", p)

// ✅ 交给 baseURL / proxy
this.$get("/mountain", p)
```

### 错误 4：空数组直接取 `[0].xxx`

```js
// ❌ 网关没数据就崩，页面白屏
const t = res.data[0].temperature

// ✅
const t = (res.data || [])[0]?.temperature ?? "0"
```

> `?.` 可选链在项目里**没用过**（babel 支持，但老代码没写过），可以放心用。

### 错误 5：循环里 `await`

```js
// ❌ 6 个池塘 = 6 次串行等待
for (const id of ids) { await this.$get(url, { topicId: id }) }

// ✅
await Promise.all(ids.map(id => this.$get(url, { topicId: id })))
```

## 八、作业（本课唯一动手题）

**目标**：在 `src/views/` 下新建一个 `Test.vue`，访问 `/#/test` 时显示"某基地当前空气温度"，每 30 秒刷新一次，接口挂了要有提示。

**要求**：
1. 用 `async/await`；
2. 空数组不能让页面崩；
3. 组件销毁时清掉定时器；
4. 不写死 URL（用 `/mountain` 相对路径，观察它会不会走 proxy）。

**参考实现**：

```vue
<template>
  <div style="color:#fff; font-size:2rem; padding:2rem">
    <div>空气温度：{{ temp }} ℃</div>
    <div>数据时间：{{ ts }}</div>
    <div v-if="error" style="color:#ff8888">{{ error }}</div>
  </div>
</template>

<script>
export default {
  data() {
    return { temp: "--", ts: "--", error: "" };
  },
  mounted() {
    this.fetchData();
    this.timer = setInterval(this.fetchData, 30000);   // 30 秒
  },
  beforeDestroy() {
    clearInterval(this.timer);                          // ← 必须
  },
  methods: {
    async fetchData() {
      try {
        const res = await this.$get("/mountain", {
          topicId: "35",
          timeType: "realTime",
        });
        const rec = (res.data || [])[0];      // 空数组时 rec 是 undefined
        if (!rec) {
          this.temp = "--";
          this.ts = "--";
          this.error = "该网关暂无数据";
          return;
        }
        this.error = "";
        this.temp = rec.temperature ?? "--";
        this.ts = rec.ts ?? "--";
      } catch (e) {
        this.error = "请求失败：" + e.message;
      }
    },
  },
};
</script>
```

**验收标准**：
- `/#/test` 能看到真实温度（约 10.4℃）；
- 把 `topicId` 改成 `9999` → 显示"该网关暂无数据"，页面**不崩**；
- 把 `baseURL` 改错 → 显示"请求失败"，页面**不崩**。

## 九、自测题

1. `this.$get(url).then(res => res)` 里的 `res` 是什么？`this.$post(url).then(res => res)` 里的 `res` 又是什么？
2. 为什么项目里到处写 `(item.temperature - 0).toFixed(2)`？直接 `.toFixed(2)` 行不行？
3. 后端返回 `data: []` 时，`resData.map()` 和 `resData[0].x` 分别会怎样？
4. `baseURL` 什么时候不生效？举两个例子。
5. 想让 6 个池塘同时请求，代码怎么写？

### 答案

1. `$get` 的 `res` 是**后端 body**（`{code, data}`）；`$post` 的 `res` 是**整个 axios response**（`{status, headers, data:{code,data}}`）。差一层。
2. 因为后端数值是字符串（`"10.40"`）。`.toFixed()` 是 Number 的方法，字符串上没有 → `TypeError`。`"10.40" - 0` 会隐式转成数字 `10.4`，再 `.toFixed(2)` 才成立。
3. `.map()` 返回 `[]`（不报错，图表空着）；`[0].x` 抛 `TypeError: Cannot read property 'x' of undefined`（页面白/数字不变）。
4. 当 url 是绝对地址（`http://...`）时、以及 `axios.create({baseURL})` 实例上又传了绝对 url 时。本项目页面全写绝对地址，所以 baseURL 一直没生效。
5. `Promise.all(ids.map(id => this.$get(url, { topicId: id })))`。
