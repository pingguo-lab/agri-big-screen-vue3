### 3.2 `vue.config.js`（Vue 3 版）

```js
const { defineConfig } = require("@vue/cli-service");

module.exports = defineConfig({
  transpileDependencies: true,     // 让 vue-cli 把某些依赖也过一遍 babel
  publicPath: "./",                // 产物用相对路径 → 丢任意目录都能跑
  assetsDir: "large",              // 静态资源输出到 dist/large/
  productionSourceMap: false,      // 生产不生成 sourcemap（体积小一半）
  devServer: {
    port: 8080,
    hot: true,
    proxy: {
      "/api": {
        target: "http://121.5.9.113:8090",
        secure: false,
        changeOrigin: true,
        pathRewrite: { "^/api": "" },
      },
    },
  },
});
```

| 配置 | 作用 | 去掉会怎样 |
|---|---|---|
| `transpileDependencies: true` | 把依赖里的新语法也降级 | 个别库可能在老浏览器报语法错误 |
| `publicPath: "./"` | HTML 里资源前缀变 `./` | 部署到子目录 404 |
| `assetsDir: "large"` | 资源进 `dist/large/` | 资源散在 `js/`、`css/`、`img/` |
| `productionSourceMap: false` | 不打 sourcemap | dist 体积翻倍，但不影响运行 |
| `devServer.proxy` | `/api/xxx` → `http://121.5.9.113:8090/xxx` | 只有写相对路径的请求会用到（本项目 99% 写的是绝对地址，所以代理基本是摆设） |

**和 Vue 2 版的差异**：

```js
// Vue 2 版有这一行（其实没用上，模板都在 .vue 里预编译了）
runtimeCompiler: true,
```

Vue 3 版删掉了；`defineConfig` 只是包一层，为了有类型提示（纯 JS 项目也能用）。

## 四、`public/index.html`（没变）

```html
<div id="app">
  <div id="loader-wrapper">
    <div id="loader"></div>
    <div class="loader-section section-left"></div>
    <div class="loader-section section-right"></div>
    <div class="load_title">正在加载中...</div>
  </div>
</div>
```

**转圈是怎么消失的**：

Vue 3 的 `app.mount("#app")` 和 Vue 2 一样，内部做的是

```js
container.replaceChild(vm.$el, container.firstElementChild)   // 用渲染结果替换 #app 的内容
```

`#loader-wrapper` 在 `#app` **里面** → 被一起替换掉 → 转圈消失。

> 那 200 行 `.loaded` 动画 CSS（`index.html` 第 122~151 行）**从来没被触发过**，
> 全项目没有任何 `classList.add("loaded")`，属于死代码。**Vue 3 版依然保留着**（不影响运行）。

**验证实验**：把 `main.js` 最后一行 `app.mount("#app")` 注释掉 → 页面永远停在转圈。

## 五、`src/main.js` 逐段（64 行，全项目最该背的文件）

### 5.1 全文（带注释）

```js
// ① 框架与壳
import { createApp } from "vue";        // ★ Vue 2 是 import Vue from "vue"
import App from "./App.vue";
import router from "./router";
import store from "./store/store";

// ② 第三方
import * as echarts from "echarts";
import axios from "axios";
import ElementPlus from "element-plus";
import "element-plus/dist/index.css";   // Vue 2 是 element-ui/lib/theme-chalk/index.css

// ③ 本地工具
import { postRequest, getRequest } from "./utils/request.js";
import { average, pushData, getBarTime } from "./utils/average.js";

// ④ 副作用引入（没有 export，import 即执行）
import "./assets/js/chalk";             // 内部执行 echarts.registerTheme('chalk', {...})
import "./assets/css/global.css";       // html/body/#app 撑满 + 背景

// ⑤ Vue 3 兼容层（替换 3 个 Vue 2 专用库）
import DataViewCompat from "./compat/data-view";
import SwiperCompat from "./compat/swiper";
import SeamlessScroll from "./compat/seamless-scroll";

// ⑥ 请求拦截器
axios.interceptors.request.use((config) => {
  const token = window.localStorage.getItem("token");
  if (token && (config.url || "").includes("/export")) {
    config.headers.Authorization = token;
  }
  return config;
});

// ⑦ 创建应用实例
const app = createApp(App);

app.use(router);
app.use(store);
app.use(ElementPlus);
app.use(DataViewCompat);
app.use(SwiperCompat);

// ⑧ 全局组件注册（Vue 2 里是 Vue.use(某个组件)，Vue 3 必须 app.component）
app.component("vue-seamless-scroll", SeamlessScroll);
app.component("VueSeamlessScroll", SeamlessScroll);

// ⑨ 全局属性（Vue 2 是 Vue.prototype.$xxx）
Object.assign(app.config.globalProperties, {
  $echarts: echarts,
  $post: postRequest,
  $get: getRequest,
  $average: average,
  $pushData: pushData,
  $getBarTime: getBarTime,
  $axios: axios,
});

// ⑩ 全局错误兜底（Vue 3 新增能力，能拿到出错组件）
app.config.errorHandler = (err, instance, info) => {
  const name =
    (instance && instance.$options && (instance.$options.name || instance.$options.__file)) || "unknown";
  console.error("[VUE-ERR]", err && err.message, "| component:", name, "| info:", info);
};

// ⑪ 挂载
app.mount("#app");
```

### 5.2 与 Vue 2 版逐行对照

| 段 | Vue 2 | Vue 3 | 为什么 |
|---|---|---|---|
| ① | `import Vue from "vue"` | `import { createApp } from "vue"` | Vue 3 没有默认导出 |
| ⑦ | `new Vue({ router, store, render: h => h(App) })` | `createApp(App)` + `app.use(...)` | 实例化与配置分离 |
| ⑦ | `render: (h) => h(App)` | 不需要 | 根组件直接作为参数 |
| ⑧ | `Vue.use(borderBox8)` | `app.component("dv-border-box-8", borderBox8)` | `Vue.use` 只接受有 `install` 的插件 |
| ⑨ | `Vue.prototype.$get = ...` | `app.config.globalProperties.$get = ...` | 不再污染全局 |
| ⑩ | 无（要装 `vue-errorhandler` 或全局 `window.onerror`） | `app.config.errorHandler` | 内置 |
| ⑪ | `.$mount("#app")` | `.mount("#app")` | 少个 `$` |

### 5.3 `$echarts` 为什么能省掉一堆 `import`

`app.config.globalProperties` 相当于给**所有组件实例**挂属性：

```js
app.config.globalProperties.$get = getRequest;
// 之后任何组件里：
this.$get("/mountain", { topicId: "35" });
```

模板里也能直接用：`{{ $echarts.version }}`。

**代价**：来源不明显（看代码不知道 `$get` 从哪来），所以大型项目更推荐 `import`。
本项目沿用 Vue 2 的习惯，迁移时保留了这一套。

### 5.4 `chalk.js` 为什么要从 UMD 改成 ESM

Vue 2 版里它是 UMD 包装：

```js
(function (root, factory) {
  if (typeof exports === 'object') factory(exports, require('echarts'));   // webpack 4 走这条
  else factory({}, root.echarts);
}(this, function (exports, echarts) { ... }));
```

Vue 3 版（webpack 5）里这套判断的行为变了，而且直接改成 ESM 更确定：

```js
import * as echarts from "echarts";

// 原 UMD 函数体里有 return 语句，不能裸露在模块顶层，所以包一层 IIFE
(function () {
  if (!echarts) { log("ECharts is not Loaded"); return; }
  echarts.registerTheme("chalk", { /* 400 行主题配置 */ });
})();
```

**验证**：如果主题没注册成功，图表坐标轴文字会变成深灰（几乎看不见）——这就是迁移初期我截图发现的第一个问题。

## 七、一次刷新的完整时序

```
① npm run serve
   └─ vue-cli-service（webpack 5）监听 8080

② 浏览器 GET /
   └─ index.html（含 #app + loader）
      └─ 2 个 script：
         large/js/chunk-vendors.js   ← vue/echarts/element-plus/three…
         large/js/app.js             ← main.js + router + store

③ 执行 app.js
   └─ main.js：装插件 → 注册全局组件/属性 → createApp().mount("#app")
      └─ #app 内容被替换（loader 消失）

④ App.vue → <router-view> → hash = #/jinggang
   └─ 动态 import 对应 chunk（首次下载）
      └─ ScreenPage.vue mounted → 发请求 → 渲染

⑤ 改代码保存
   └─ webpack 增量编译 → WebSocket → HMR 组件替换
```

## 九、报错急救（Vue 3 特有）

| 现象 | 原因 | 处理 |
|---|---|---|
| `Module not found: Can't resolve 'url'` / `'path'` / `'buffer'` | **webpack 5 不再自动 polyfill Node 内置模块** | 换浏览器版依赖（如 `mqtt/dist/mqtt.min.js`）或在 `vue.config.js` 里配 `resolve.fallback` |
| `export 'default' was not found in 'vue'` | Vue 3 没有默认导出 | 改成 `import { createApp } from "vue"` |
| `export 'default' was not found in 'vue-router'` | vue-router 4 没有默认导出 | 改成具名导入 `createRouter` |
| `Cannot read properties of null (reading 'xxx')` + 图表 | ECharts 实例被响应式代理 | `markRaw(echarts.init(...))` |
| `[VUE-ERR]` 日志出现 | 全局兜底捕获 | 看后面的 `component:` 字段定位文件 |
| `TypeError: app.use is not a function` | 把组件当插件传了 | 组件用 `app.component` |
| 白屏 + `defineProps is not defined` | 用了 `<script setup>` 但没导入 | `import { defineProps } from "vue"` 或直接写在宏里 |
| 样式全丢 | 忘了 `element-plus/dist/index.css` | 检查 `main.js` 第 10 行 |
| 端口占用 `EADDRINUSE :8080` | 另一个 serve 还在跑 | `netstat -ano \| findstr :8080` → `taskkill /PID xxx /F` |

## 十、小结

```
npm run serve
  → webpack5 devServer(8080)
  → 浏览器拿 index.html（#app + loader）
  → 下 app.js + chunk-vendors.js
  → main.js：app.use(...) → globalProperties → app.mount("#app")
  → #app 被替换（loader 消失）
  → App.vue 的 router-view → hash 路由懒加载 ScreenPage → 像素
```

四句话：

1. `index.html` 是**坑**，`main.js` 是**挂载**，`App.vue` 是**壳**，`router` 决定**塞什么**。
2. Vue 3 的入口是"**先 createApp，再 app.use**"，不再是 `new Vue({ router })`。
3. 全局能力从 `Vue.prototype` 搬家到 `app.config.globalProperties`。
4. 首屏 loader 消失靠"元素被替换"，那套 `.loaded` CSS 是死代码（Vue 3 版仍保留）。

## 十一、自测

1. `npm run serve` 之后磁盘上有产物吗？
2. `createApp` 和 `new Vue` 的本质区别是什么？
3. `app.config.globalProperties.$get` 和 `import { getRequest }` 各适合什么场景？
4. 为什么 webpack 5 会报 `Can't resolve 'url'`？
5. 转圈动画是谁弄消失的？

<details><summary>答案</summary>

1. 没有，全在内存里；只有 `npm run build` 才产出 `dist/`。
2. 前者是"每个应用一个实例"，配置不污染全局；后者是"全局构造函数"，全站共用一份配置。
3. 前者方便（模板里直接用 `this.$get`），但来源不透明；后者显式，适合大型项目和按需打包。
4. webpack 5 移除了 Node 内置模块的自动 polyfill（webpack 4 会偷偷带上）。
5. `app.mount("#app")` 会把 `#app` 的内容整体替换成 `App.vue` 的渲染结果，loader 在里面，于是被替换掉。

</details>
