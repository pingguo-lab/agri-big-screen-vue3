```
 App running at:
 - Local:   http://localhost:8080

```

### 那 6 个警告是什么

全部是同一个原因，来自 postcss：

```
warning  in ./src/views/YuganAqua/ScreenPage.vue?vue&type=style...
(184:3) end value has mixed support, consider using flex-end instead
```

含义：CSS 里写了 `align-items: end`，老浏览器不认，建议写 `flex-end`。
**结论：与功能无关，可以忽略**。学会区分"警告"和"错误"是第一步 ——
`Compiled with N warnings` 是成功；`Failed to compile` 才是失败。

### 一个副作用要说明

`npm install` 时 npm 11 把 `package-lock.json` 的 `lockfileVersion` 从 2 升级到了 3
（文件从 400845 字节变成 411388 字节）。这是 npm 版本差异导致的正常行为，
不影响运行；如果在意，用 `git checkout package-lock.json` 还原即可（本项目不是 git 仓库，忽略）。

### 3.1 `package.json`

```json
{
  "name": "agri-big-screen",
  "version": "0.1.0",
  "private": true,
  "scripts": {
    "serve": "vue-cli-service serve",
    "build": "vue-cli-service build",
    "lint": "vue-cli-service lint"
```

- **`name` 是 `agri-big-screen`（农业大屏），不是"井冈山"** —— 说明这个仓库本来是给多个基地做的大屏基座，

- `browserslist` 决定 babel 要降级到多老、autoprefixer 要加哪些前缀。
  `> 1%` 意味着**会兼容一部分老浏览器**，所以代码里还能看到 `.toFixed()`、`String.prototype.slice` 这种保守写法。

### 3.4 `.eslintrc.js` —— 为什么项目里 `console.log` 遍地

```js
module.exports = {
  root: true,
  env: { node: true },
  extends: ["plugin:vue/essential", "eslint:recommended"],
  parserOptions: { parser: "babel-eslint" },
  rules: {

    "no-debugger": process.env.NODE_ENV === "production" ? "warn" : "off",

```

1. `"no-unused-vars": "off"` —— 允许声明不用的变量（所以 `let resData` 用完不解构也没人管）；

   → 这就是为什么 `data()` 里混着双引号/单引号、缩进 2 空格/4 空格，全都能过。

## 四、构建器：`vue.config.js` 逐项拆

```js
module.exports = {
  runtimeCompiler: true,
  publicPath: "./",
  assetsDir: "large",
  devServer: {
    port: 8080,
    hot: true,
    proxy: {
      "/api": {
        target: "http://121.5.9.113:8090",
        secure: false,
        changeOrigin: true,
        pathRewrite: { "^/api": "" },
      },
    },
  },
};
```

### ① `runtimeCompiler: true` —— 让 Vue 带上"模板编译器"

- Vue 有两种构建：**运行时版**（只能写 render 函数/`.vue` 文件）和**完整版**（还能在 JS 里写 `template: "<div>{{a}}</div>"`）。
- 这个项目把 `.vue` 文件都交给 `vue-loader` 预编译了，**根本不需要运行期编译**。
  我在 `src/` 里搜 `template:` 只有 14 处命中，全是 EZUIKit 播放器的参数 `template: "standard"`，不是 Vue 的模板选项。
- 结论：**这一项可以删**，删了包体小 10~20KB（gzip），启动更快。留着也不会错，只是浪费。
- 想验证：删掉这行 → `npm run serve` → 页面照常（因为没用到）。

### ② `publicPath: "./"` —— 打包产物的相对路径前缀

- 默认是 `"/"`，打包后 `index.html` 里写的是 `<script src="/large/js/app.js">`，
  **部署到子目录（如 `http://x.com/daping/`）就会 404**。
- 改成 `"./"` 后写的是 `./large/js/app.js`，**放到哪都能跑**。
- 这是"政府/园区项目常见交付方式"（甲方随便给个目录就上传）的标准解法。

### ③ `assetsDir: "large"` —— 静态资源输出目录名

- 默认 `js/`、`css/`、`img/`，这里改成全部塞进 `large/` 下。
- **实测证据**：dev 环境下抓首页 HTML，注入的 script 是

```html
<script src="large/js/chunk-vendors.js"></script>
<script src="large/js/app.js"></script>
```

  而我直接访问 `/js/app.js` 返回 **404**，访问 `/large/js/app.js` 才是 200 —— 说明 `assetsDir` 生效了。

### ④ `devServer.proxy` —— 开发期代理（本项目基本是摆设）

```js
"/api": { target: "http://121.5.9.113:8090", changeOrigin: true, pathRewrite: { "^/api": "" } }
```

规则翻译：前端请求 `/api/xxx` → 开发服务器转发到 `http://121.5.9.113:8090/xxx`（去掉 `/api` 前缀）。
`changeOrigin: true` 把请求头里的 `Host` 改成目标域名，骗过后端的域名校验。

**为什么说是摆设**：页面里写的是绝对地址

```js
this.$get("http://121.5.9.113:8090/mountain", { topicId: "35" })
```

axios 遇到绝对 URL 会**直接忽略 baseURL，也不会经过 devServer**，所以代理没参与。
全项目只有一处真用到了代理：`views/YuganAqua` 里 `axios.get("/api/get-cities")`，
它会被转发成 `http://121.5.9.113:8090/get-cities`。

> 这也解释了为什么本地开发会跨域 —— 靠的是后端配了 CORS，不是靠代理。

## 五、入口 HTML：`public/index.html`

### 5.1 三个模板变量

```html
<link rel="icon" href="<%= BASE_URL %>favicon.ico">
<title>智慧农业采集信息展示系统</title>
<strong>We're sorry but <%= htmlWebpackPlugin.options.title %> doesn't work properly ...</strong>
```

- `<%= BASE_URL %>` 由 vue-cli 注入，值就是 `publicPath`（`./`）。
- `<%= htmlWebpackPlugin.options.title %>` —— 这个值来自 `package.json` 的 `name`
  （`agri-big-screen`），而 `<title>` 又被手写成了中文。
  **两处不一致**：真实生效的是 `<title>`，noscript 里那句英文才是 `name`。
- 结论：`title` 想改就改 `index.html` 第 9 行。

### 5.2 那个转圈动画的真相（本课最有意思的发现）

`index.html` 里有一段 200 行的 CSS，定义了 `#loader-wrapper`、`#loader`、
`.loader-section.section-left/right` 和 `.loaded` 状态下的一系列动画，HTML 是：

```html
<div id="app">
  <div id="loader-wrapper">
    <div id="loader"></div>
    <div class="loader-section section-left"></div>
    <div class="loader-section section-right"></div>
    <div class="load_title">正在加载中...</div>
  </div>
</div>
```

问题来了：`#loader-wrapper` 在 `#app` **里面**。

Vue 2 的 `$mount("#app")` 行为是：**用渲染结果整体替换掉 `#app` 这个元素**。
所以 `main.js` 一执行完，那一堆 loader 的 DOM 连同它的 CSS 一起被扔掉，
页面上自然就"消失"了 —— **不是靠 `.loaded` 类，是靠元素被替换**。

再验证一下：全项目搜 `classList.add("loaded")`、`"loaded"` 字符串 —— **0 处**。
也就是 CSS 里那套 `.loaded ...` 过渡动画（第 122~151 行）**从来没被触发过，是死代码**。

> 这是个很好的"读代码要交叉验证"的例子：注释/样式告诉你"应该这样"，但没人调用它。

### 5.3 那个空的 CSP

```html
<meta http-equiv="Content-Security-Policy">
```

值为空 = **没有生效**。原作者想限制资源加载（大屏常配内网白名单），但写法不对（CSP 要写成
`content="default-src 'self' ..."`）。当前等于没写，可以删。

### 6.1 带注释版（逻辑与原文一致）


> 注：原文第 12~13 行是 `import "./assets/js/chalk";` 和 `import "./assets/css/global.css";`，
> 且 `import axios from "axios"` 在第 15 行 —— 我把 import 归了类，顺序略有调整以便阅读，
> 但**副作用执行顺序不能乱**（下面 6.2 讲）。

### 6.2 为什么 import 顺序不能乱

```js
import * as echarts from "echarts";   // 必须在前：chalk.js 里要拿 echarts 注册主题
import "./assets/js/chalk";           // 依赖 echarts 已经加载
import "element-ui/lib/theme-chalk/index.css";
import "./assets/css/global.css";     // 放在最后：可以覆盖 element 的默认样式
```

`chalk.js` 是 UMD 格式：

```js
(function (root, factory) {
    if (typeof exports === 'object') factory(exports, require('echarts'));  // 走这条
    ...
}(this, function (exports, echarts) {
    if (!echarts) log('ECharts is not Loaded');
    echarts.registerTheme('chalk', { ... });
}));
```

它内部**自己又 `require('echarts')` 了一次**，所以就算顺序反了也不会报错，
但一旦项目里出现过两份 echarts 实例，主题就会注册到另一份上，
表现为"图表是白底、主题没生效"——这类问题很难查，所以顺序照抄别动。

### 6.3 原型挂载表（记住这张表，后面所有页面都用它）

| 原型方法 | 来源 | 典型用法 |
|---|---|---|
| `this.$echarts` | echarts 全量 | `this.$echarts.init(this.$refs.curve, "chalk")` |
| `this.$get(url, params)` | `getRequest` | `this.$get("/mountain", {topicId:"35"})` |
| `this.$post(url, params)` | `postRequest` | `this.$post("https://open.ys7.com/api/lapp/device/ptz/start?...")` |
| `this.$axios(config)` | axios 原对象 | 登录、导出（需要自定义 headers/responseType） |
| `this.$average(arr)` | average.js | 求平均、字符串转数字、空值补 0 |
| `this.$pushData(arr)` | average.js | 每 13 条切一小时，返回 6 个小时均值 |
| `this.$getBarTime(time)` | average.js | 生成柱状图 X 轴的时间标签 |

### 6.4 拦截器里的那个 bug（现在就记住）

```js
if (config.url == "http://121.5.9.113:8090/api/v1/export")
```

- 用的是 `==` **全等比较**，一字不差才命中；
- 而实际导出页 `views/ExportPage/ExportPage.vue` 请求的是：

```js
url: "http://121.5.9.113:8090/api/v1/allMsg/export"
```

多了 `allMsg/` → **条件永远不成立 → token 从来没被带上**。
正确写法：

```js
axios.interceptors.request.use((config) => {
  const token = localStorage.getItem("token");
  if (token) config.headers.Authorization = token;   // 或只对 /export 结尾的加
  return config;
});
```

顺带：`console.log(config)` 会把 token 打进控制台，属于信息泄露，生产环境要删。

## 七、`App.vue` 与"壳"的概念

```vue
<template>
  <div id="app">
    <router-view></router-view>
  </div>
</template>

<style>
#video5-container iframe,
#FxVideo1-container iframe,
#FxVideo2-container iframe {
  height: 100% !important;
  width: 100% !important;
}
</style>
```

两个知识点：

1. **`<router-view>` 就是"坑"**。所有 23 个页面都往这个坑里塞。改这里 = 改所有页面的外壳。
2. **为什么这三条 iframe 样式不带 `scoped`**：EZUIKit 播放器会在容器里动态生成 `<iframe>`
   （萤石云的播放内核跑在 iframe 里）。子组件用 `scoped` 生成的 `[data-v-xxx]` 选择器
   **管不到运行期才插入的 iframe**，所以只能写在全局。`!important` 是为了压过播放器内联样式。

## 八、一次刷新的完整时序（对照 F12 Network）

打开 `http://localhost:8080/#/jinggang`，Network 勾选 JS，你会看到（实测）：

```
① GET /                      200   ~6.9KB    ← index.html（含 loader）
② GET /large/js/chunk-vendors.js   ← vue + echarts + element-ui + three 等公共依赖
③ GET /large/js/app.js             ← main.js + router + store 你的业务代码
④ GET /large/js/xxx.js             ← 懒加载的 JgMountain chunk（点进来才下）
```

- 为什么只有 2 个同步 script：因为路由全是 `() => import(...)`，webpack 把每个页面拆成
  **独立 chunk**，用 JSONP 动态插 `<script>`。
- 这带来一个直观好处：首屏不下载 16 个大屏的代码；也带来一个坑：
  **首次点某个大屏会白屏一下**（正在下 chunk）。

链路图：

```
package.json (scripts.serve)
   └─ vue-cli-service serve
        ├─ 读 vue.config.js      → 端口/代理/路径前缀
        ├─ 读 babel.config.js    → 把 ES6+ 转成旧浏览器能跑的
        ├─ 读 .eslintrc.js       → 边编译边检查
        └─ webpack 启动 devServer :8080
              │
浏览器 GET / ─┴→ public/index.html（注入 2 个 script）
              │
              ├→ chunk-vendors.js（第三方）
              └→ app.js
                    └─ main.js：装插件 → 挂原型 → new Vue().$mount("#app")
                          └─ App.vue 的 <router-view>
                                └─ hash = #/jinggang → 懒加载 chunk
                                      └─ JgMountain/ScreenPage.vue 渲染成像素
```

## 九、动手实验（每个都有"预期现象"，做完再往下）

### 实验 A：改标题（1 分钟）
改 `public/index.html` 第 9 行 `<title>`。刷新标签页。
**预期**：浏览器标签文字变了，页面内容不变。
**为什么**：`<title>` 属于 HTML 模板，与 Vue 无关。

### 实验 B：加全局代码（2 分钟）
在 `main.js` 的 `new Vue(...)` 之前加：

```js
console.log("boot ok", Vue.version, process.env.NODE_ENV);
```

**预期**：控制台输出 `boot ok 2.6.14 development`（版本号以你装的为准）。
**为什么**：`process.env.NODE_ENV` 是 webpack 在编译期**字符串替换**进去的，不是运行时变量。

### 实验 C：让 loader 永远转（3 分钟，验证 5.2 的结论）
把 `main.js` 最后一行改成：

```js
// new Vue({ router, store, render: (h) => h(App) }).$mount("#app");
```

**预期**：页面永远停在"正在加载中…"的蓝色转圈。
**为什么**：没有 Vue 挂载 → `#app` 里的 loader DOM 没被替换 → 一直显示。
**做完改回来。**

### 实验 D：把壳换掉（3 分钟）
把 `App.vue` 的 `<router-view>` 换成 `<h1 style="color:#fff">hello</h1>`。
**预期**：无论访问 `/#/jinggang` 还是 `/#/navigation`，都只看到 hello。
**为什么**：路由只决定"往坑里塞什么"，坑没了就什么都不显示。

### 实验 E：关掉 runtimeCompiler（5 分钟）
注释 `vue.config.js` 里 `runtimeCompiler: true`，重启 `npm run serve`。
**预期**：一切照常（因为项目没有运行期模板）。
**说明**：这就是"配置项存在 ≠ 配置项被需要"。

## 十一、本课小结（背这张图）

```
npm run serve
  → webpack(devServer:8080) 读 vue.config.js / babel / eslint
  → 浏览器拿 index.html（内含 #app + loader）
  → 下 app.js + chunk-vendors.js
  → main.js: 装插件 → import 副作用(chalk/global.css) → 挂原型 → new Vue().$mount("#app")
  → #app 被整体替换（loader 顺带消失）
  → App.vue 的 <router-view>
  → hash 路由懒加载对应 ScreenPage chunk
  → 渲染成像素
```

四句话：
1. `index.html` 是**坑**，`main.js` 是**挂载**，`App.vue` 是**壳**，`router` 是**塞什么**。
2. `vue.config.js` 决定**怎么打包**（前缀、资源目录、端口、代理）。
3. `main.js` 的原型挂载决定**你能写什么语法**（`this.$get`）。
4. 首屏 loader 的消失靠"元素被替换"，不靠那套 `.loaded` 动画（死代码）。

## 十二、自测题（答案在第十三节，先自己答）

1. 页面顶部那个"正在加载中…"的转圈，是谁、在什么时机弄消失的？
2. `vue.config.js` 里 `publicPath` 和 `assetsDir` 分别影响什么？举一个因为写错而 404 的场景。
3. `main.js` 里 `import "./assets/js/chalk"` 为什么不需要 `from`？它做了什么？
4. 为什么模板里能直接写 `this.$get(...)`，而不用在每个组件里 `import { getRequest }`？
5. `devServer.proxy` 为什么在这个项目里几乎没生效？什么情况下会生效？

## 十三、自测答案

1. `new Vue(...).$mount("#app")` 执行时，Vue 2 会用渲染结果**替换整个 `#app` 元素**，
   loader 的 DOM 在 `#app` 内部，于是被一起扔掉。`.loaded` 那套 CSS 没有任何 JS 触发，是死代码。
2. `publicPath` 决定 HTML 中资源引用的前缀（`./` 相对 / `/` 绝对），影响能否部署到子目录；
   `assetsDir` 决定输出到 `large/` 还是 `js/`、`css/`。写错就 404（实测 `/js/app.js` 是 404，`/large/js/app.js` 是 200）。
3. 它是**副作用模块**：文件里没有 export，但执行时会 `echarts.registerTheme('chalk', {...})`，
   把主题注册进全局 echarts。`import` 本身就是"执行一次"。
4. 因为 `main.js` 里做了 `Vue.prototype.$get = getRequest`，原型链上的方法，所有组件实例都能访问。
5. 因为页面里写的是**绝对 URL**（`http://121.5.9.113:8090/...`），axios 对绝对 URL 不套 baseURL、也不走 devServer。
   只有写相对路径（如 `/api/get-cities`）才会命中代理。
