### 2.1 三种写法，各有含义

| 写法 | 含义 | 例子 |
|---|---|---|
| `redirect` | 只有"跳转"，没有组件 | `/` → `/navigation` |
| `component: () => import(...)` | **懒加载**（动态 import） | 所有大屏 |
| `component: Home` | 静态引入（打进主包） | 本项目没用 |

### 2.2 懒加载到底懒在哪

```js
component: () => import("../views/JgMountain/ScreenPage.vue")
```

- 这不是立即执行，而是返回一个 **Promise 工厂**；
- webpack 在打包时看到 `import()` 语法，就把该文件**单独切一个 chunk**；
- 只有路由命中时，vue-router 才调用这个函数 → webpack 用 JSONP 动态插一个 `<script>` 下载 chunk。

**Network 面板验证**：
1. 打开 `http://localhost:8080/#/navigation`，只会有 `app.js` + `chunk-vendors.js`；
2. 点"井冈山黄桃"卡片 → Network 里会**多出一个新的 js 请求**（就是 JgMountain 的 chunk）；
3. 再点别的基地 → 又多一个。

这就是为什么"首次点某块屏会白一下"——正在下 chunk。

### 2.3 `beforeEach` 里的 404 兜底

```js
if (to.matched.length === 0) next("/error");
```

- `to.matched` 是"匹配到的路由记录数组"，一个都没匹配上就是空数组；
- 比 `path="*"` 写法更直接，效果一样。

⚠️ 小坑：`next("/error")` 在 `/error` 本身也匹配失败时会**死循环**。
本项目 `/error` 是存在的，所以安全。更稳的写法：

```js
if (to.matched.length === 0) {
  next(to.path === "/error" ? false : "/error");
}
```

### 2.4 为什么不配 `path="*"` 也能兜住

因为 `beforeEach` 是**全局前置守卫**，它的判断发生在渲染之前。
这比 `*` 路由更早、更"通用"。

## 三、`hash` vs `history`：本项目的关键选择

```js
mode: "hash"    // URL 长这样：http://x.com/#/jinggang
```

| | hash 模式 | history 模式 |
|---|---|---|
| URL | `/#/jinggang` | `/jinggang` |
| 刷新页面 | ✅ 正常（`#` 后面不发请求） | ❌ 404，除非服务器把所有路径 rewrite 到 index.html |
| 部署要求 | 丢到任意静态目录即可 | 必须配 nginx `try_files` / IIS rewrite |
| 观感 | 多个 `#` | 更干净 |

**配合 `vue.config.js` 的 `publicPath: "./"`**，本项目可以做到：
> 把 `dist/` 整个文件夹拷到任何地方（甚至 U 盘、内网文件服务器），双击就能跑。

这是"交付给甲方"最省事的方案，所以大屏项目几乎都用 hash。

**实验**：把 `mode` 改成 `"history"` → `npm run serve` → 访问 `http://localhost:8080/jinggang` → **F5 刷新 → 404**。
devServer 有 fallback，所以本地可能看不出问题，但打包后丢到 nginx 一定会 404。

```html
    <div class="item"><yuganFish /></div>
    <div class="item"><mjy/></div>
    <!-- 保证每排 4 个组件，如果不符，此处的数字 -->
    <div class="item" v-for="(o, i) in 2" :key="i"></div>
  </div>

  <div class="copyright">…赣ICP备2021011411号-1…</div>

```

### 4.2 CSS 布局原理

```less
.menu {
  display: flex;
  height: 85%;
  overflow: auto;
  margin: 0 auto;
  margin-top: 20px;
  flex-wrap: wrap;                 // ★ 放不下就换行
  justify-content: space-evenly;   // ★ 每行均分左右留白
  .item {
    margin: 20px auto;
    width: 400px;                  // ★ 固定宽度
    height: 250px;
  }
}
.menu::-webkit-scrollbar { display: none; }   // 藏滚动条
```

计算一下 4 列的由来：屏幕 1920，4 × 400 = 1600，剩 320 由 `space-evenly` 分成 5 份，
所以看起来是**卡片等间距铺满一行**。窗口变窄 → 自动变 3 列 / 2 列。

### 4.3 那两个空 `div` 是干什么的

`<div class="item" v-for="(o, i) in 2" :key="i"></div>` 渲染出 **2 个空盒子**。

为什么？因为注释写得很清楚："**保证每排 4 个组件**"。
8 张卡片正好 4×2 排满，多出来的 2 个空盒子是为了**以后加卡片时**（比如加到 9、10 张）
让最后一行仍然对齐左起、不被 `space-evenly` 挤到中间。

> 结论：这是"复制粘贴式开发"留下的补丁，不是 bug，但很脆 ——
> 一旦卡片数量变了，就得手动改这个数字，所以原作者才写了大段注释提醒。

### 4.4 被注释掉的 4 张卡

```js
//import farmLand from "../components/farmLand";
//import yibinPlum from "../components/yibinPlum";
//import yuganAqua from "../components/yuganAqua.vue";
//import xiaofuchaye from "../components/xiaofuchaye.vue";
```

对应 4 个基地的地图组件都还在 `components/` 里，只是首页不显示了。
**这意味着：只要取消注释 + 补 `components` 注册，就能多 4 张卡**（但记得改占位数）。

### 4.5 import 写法的混乱（可以统一）

```js
import jinggangShan from "../components/jinggangShan";        // 不带扩展名
import XinjianEcoGarden from "../components/xinjianEcoGarden.vue";  // 带 .vue
```

两种都能跑（webpack 会补 `.vue`），但风格不统一。建议统一成**带 `.vue`**，编辑器跳转更准。

### 5.3 小地图：`registerMap` 全流程

```js
import yongxinMP from "../assets/js/yongxin.json";   // ① 直接把 GeoJSON 当模块引入
```

```js
initEchartInfo() {
  let echarts = require("echarts");                                  // ② 这里是 CommonJS
  echarts.init(document.getElementById("echartInfo")).dispose();      // ③ 先销毁旧实例
  let myChart = echarts.init(document.getElementById("echartInfo"));  // ④ 再初始化
  echarts.registerMap("yongxin", yongxinMP);                          // ⑤ 注册地图
  myChart.setOption(this.option);                                     // ⑥ 设置配置
}
```

配合 `data.option`：

```js
option: {
  series: [{
    type: "map",
    map: "yongxin",                  // ★ 必须和 registerMap 的第一个参数一致
    itemStyle: { emphasis: { areaColor: "rgb(147,235,248)" } },  // 鼠标悬停变亮
    label: { show: false },          // 不显示地名
    data: [{ name: "永新县", value: 360830 }],   // 想高亮的区域
  }],
}
```

**六个知识点，逐个说清：**

1. **JSON 可以直接 `import`**：webpack 原生支持 `.json`，等同于 `module.exports = {...}`，
   不需要 loader（这也是为什么 `assets/js/*.json` 能直接给 ECharts 用）。
2. **`require("echarts")` 和 `import` 混用**：项目里既有 `import * as echarts`（main.js），
   又在这里 `require("echarts")`。webpack 会把它们指向**同一个模块实例**，所以能跑。
   但风格混用不好，建议统一 `import * as echarts from "echarts"`。
3. **`init().dispose()` 的怪写法**：
   - 如果该 DOM 上已有实例，`init` 会返回旧实例；
   - `dispose()` 销毁它，避免重复 `init` 报 "There is a chart instance already initialized on the dom"；
   - 然后再 `init` 拿一个干净的。
   - 正确做法是 `const inst = echarts.getInstanceByDom(el); if (inst) inst.dispose();`，
     但这里"先建再毁"也能达到目的，只是多建一次。
4. **`registerMap` 要放在 `setOption` 之前**：否则 `series.map` 找不到名字，图会空白。
5. **地图名要和 GeoJSON 里的 `name` 对上**：`data` 里写 `"永新县"`，
   这个字符串必须出现在 JSON 的 `properties.name` 里，否则不会有高亮。
6. **固定 id 手工编号**：`echartInfo`、`echartInfo2` … `echartInfo12`，每个卡片一个编号。
   - 为什么不用同一个 id？因为 8 张卡片**同时存在**于页面，`getElementById` 只会拿到第一个；
   - 但手工编号很脆，正确做法是用 `ref`：

```js
// 模板：<div class="echartInfo" ref="echartInfo"></div>
this.myChart = echarts.init(this.$refs.echartInfo);
```

### 5.4 "图片轮播"其实是假轮播（重点）

模板里只有**两张图片**，靠换 class 实现"前后切换"：

```html
<div class="article-main" @mouseover="mouseOver()" @mouseleave="mouseLeave()">
  <img src="../assets/images/chaye.webp"      :class="v1" />
  <img src="../assets/images/chatian-min.webp" :class="v2" />

  <div class="dot-view">
    <div :class="dot1"></div>
    <div :class="dot2"></div>
  </div>

  <div class="arrow-view" v-show="isActive">
    <img src="../assets/images/arrow1.png" class="arrow-left"  @click="toLeft()" />
    <img src="../assets/images/arrow2.png" class="arrow-right" @click="toRight()" />
  </div>
</div>
```

样式里定义了两个"位置"：

```less
.wz3 { width: 280px; height: 160px; left: 15px; top: 2px; z-index: 999; }  // 大、在最前
.wz2 { width: 50%; left: 100px; top: 20px; z-index: 888; }                 // 小、在后面
```

状态机只有两个值：

```js
data() {
  return {
    value: 1,
    v1: "banner wz3",   // 第一张：大图
    v2: "banner wz2",   // 第二张：小图
    dot1: "dot-1 dot-color-actived",
    dot2: "dot-2 dot-color-normal",
    isActive: false,    // 鼠标是否悬停（控制箭头显隐）
    timer: "",
  };
}
```

切换逻辑：

```js
toRight() {
  this.value++;
  if (this.value > 2) this.value = 1;   // 循环
  this.changeClasss();
},
changeClasss() {
  if (this.value == 1) { this.v1 = "banner wz3"; this.v2 = "banner wz2"; }
  if (this.value == 2) { this.v1 = "banner wz2"; this.v2 = "banner wz3"; }
},
```

自动播放 + 悬停暂停：

```js
mounted() {
  this.initEchartInfo();
  this.timer = setInterval(this.get, 3000);   // 每 3 秒切一张
},
mouseOver() { this.isActive = true; clearInterval(this.timer); },
mouseLeave() { this.isActive = false; this.timer = setInterval(this.get, 3000); },
beforeDestroy() { clearInterval(this.timer); },   // ✅ 这点做得对
```

**为什么不直接用 swiper？** 因为要的是"两张图叠在一起、一大一小、3D 景深"的效果，
用 CSS `position:absolute` + `transition` 换 class 更省事。
代价是：加第三张图就得再加一个 `.wz1` 和一套 if 分支（`.wz1` 已经写好了但没用）。

⚠️ `changeClasss` 是 `changeClass` 的拼写错误（少个 e），不影响运行，但看着难受。

### 5.5 文字轮播：这才是真的 swiper

```html
<div class="text" style="overflow: hidden">
  <swiper :options="swiperOption">
    <swiper-slide><p>在永新，有一座崖石山，海拔近千米…</p></swiper-slide>
    <swiper-slide><p>崖雾茶采摘精细，制作精巧…</p></swiper-slide>
    <swiper-slide><p>具有提神、利尿、健胃…</p></swiper-slide>
  </swiper>
</div>
```

```js
swiperOption: {
  pagination: { el: ".pagination-home", clickable: true },  // ★ 死配置
  loop: true,
  autoplay: { delay: 10000, disableOnInteraction: false },
},
```

**死配置**：`pagination.el` 指向 `.pagination-home`，但整个模板里**没有这个 class 的元素**
（我搜过 12 个卡片组件，全都有这行配置，全都没有对应的 div）。
结果：分页小圆点永远不显示 —— 但因为外面 `overflow:hidden`，你也看不出来少了东西。

正确写法有两种：给 swiper 加 `<div class="swiper-pagination pagination-home" slot="pagination"></div>`，
或者干脆删掉 `pagination` 配置。

### 5.6 样式从哪来

```vue
<style lang="less" scoped>
@import url("../style/navItem.less");
</style>
```

- `lang="less"` → vue-loader 调 less-loader 编译；
- `@import` → 把 `navItem.less` 的 148 行**内联**进来；
- `scoped` → 编译后每条选择器都会加 `[data-v-xxxx]` 属性，**样式只作用于当前组件**。

⚠️ 但 `navItem.less` 里有 `.header-container`、`.text`、`.pics` 这些**通用名**，
12 个卡片各持一份，谁先加载谁生效到自己的 scoped 作用域里 ——
**改一个卡片的样式，改的是它自己那份**，不会互相影响（这是 scoped 的好处）。
反过来说：想让 12 个卡片一起改，得改 `navItem.less`（因为都被 import 了）。

## 六、文字被裁掉的那个 bug（本课要修的）

看首页卡片：每张卡片的介绍文字**最后一行被切掉一半**。

### 原因

```less
.text {
  margin-top: 0.1rem;
  height: 60px;        /* ← 写死 60px */
  width: 250px;
  color: rgb(190, 231, 234);
  background-color: rgba(31, 116, 227, 0.5);
  p { margin-top: 3px; font-family: "Times New Roman", Times, serif; }
}
```

- 文本是 16px、默认行高约 1.15 → 每行 ≈ 18px；
- 中文一句话在 250px 宽度下会折成 **4 行** ≈ 72px；
- 外层 `height:60px` + `overflow:hidden` → **第 4 行被切掉一半**。

### 三种修法

```less
/* 方案 A：放大高度（最简单，但不同文字长度表现不一致） */
.text { height: 72px; }

/* 方案 B：限行 + 省略号（推荐，最稳） */
.text {
  height: 60px;
  p {
    margin: 4px 6px 0;
    font-size: 13px;
    line-height: 18px;
    display: -webkit-box;
    -webkit-line-clamp: 3;        /* 只显示 3 行 */
    -webkit-box-orient: vertical;
    overflow: hidden;
  }
}

/* 方案 C：让 swiper 自己算高度（去掉 height，交给内容撑） */
.text { height: auto; min-height: 60px; }
```

> 方案 B 是生产项目里最常见的做法：3 行 × 18px + 4px 边距 = 58px < 60px，刚好不裁。

## 十、自测题（答案在第十一节）

1. 为什么 23 条路由全都写成 `() => import(...)`？不这么写会怎样？
2. `mode: "hash"` 解决了什么部署问题？换成 history 会在哪一步炸？
3. 首页那两个空 `<div class="item" v-for="(o,i) in 2">` 是干嘛的？删了会怎样？
4. 卡片里的小地图，`registerMap` 和 `series.map` 的关系是什么？名字不一致会怎样？
5. 为什么 12 个卡片要用 12 个不同的 id（`echartInfo`~`echartInfo12`）？更好的写法是什么？

---

## 十一、自测答案

1. 为了**代码分割**：每页单独一个 chunk，首屏只下首页。不这么写就全部打进 `app.js`，
   首屏要下载 16 个屏 + three.js + echarts-gl，能到几十 MB，白屏很久。
2. 解决"部署到子目录/纯静态服务器"的问题：`#` 后面的内容浏览器不发给服务器，所以不需要服务端 rewrite。
   换成 history，刷新 `/jinggang` 时服务器找不到该文件 → 404（除非配 `try_files`）。
3. 占位：让 `flex + space-evenly` 的网格在"卡片数不是 4 的倍数"时最后一行仍对齐。
   删了不会报错，只是加卡片后最后一行会居中/错位。
4. `registerMap("名字", GeoJSON)` 是**注册**，`series.map: "名字"` 是**引用**；
   两者不一致时 ECharts 找不到地图数据，画出来是空白（控制台可能只有一句警告）。
5. 因为 8 张卡片**同时存在**于 DOM，`document.getElementById` 只会返回第一个匹配，
   共用 id 会导致只有第一张能画图。更好的是 `ref`（Vue 管理的引用，天然不冲突）。
